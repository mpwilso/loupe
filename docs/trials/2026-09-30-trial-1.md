# Trial 1: 2026-09-30

## Setup
Four Pellwick inputs, each run once with the skill on and once with it off, in separate Claude Projects holding the same five context files and the change-request template. The same prompt was used for every run.

## Results

| Measure | Loupe | Baseline |
|---|---|---|
| Right calls | 4 of 4 | 3 of 4. No story for the payment bug; it asked for a bug template instead. |
| Known lines the input doesn't support | 0 of 15 | 0 of 12 |
| Same shape every time | Yes | No. Three layouts, and one estimate in days. |
| Confidence matching the unknowns | Yes | No. It rated the holiday change Medium with three open rules. |
| Invented behavior in acceptance criteria | 1, minor | 2 |
| Developer questions still missed | About 4 that the baseline raised | 2 that Loupe raised |
| Time | Every run under a minute | Every run under a minute |
| Edits | None | None |

The reviewer accepted all eight first drafts after a quick read.

Questions Loupe missed that the baseline raised:
- Confirmation after a skip.
- The cutoff passing while the page is open.
- Telling support before 1 December.
- Release-day timing.

Questions the baseline missed that Loupe raised:
- Whether a skip is a payments change under the freeze.
- Which system decides the next delivery date.

## The checker in claude.ai
The checker ran: no "Not checked:" line appeared. The Node version wasn't reported.

## Limits
- Four inputs, one run each.
- Scored by a reviewer who helped design Loupe.
- The baseline had Loupe-shaped context files, including a story style that teaches Loupe's format. So this measures what the skill adds on top of those files, not Loupe against plain Claude.
