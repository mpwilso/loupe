## Trial 8c: repeats

After trial 8b, the skill was told to always run the checker itself, since a denied or failed command doesn't mean the checker is denied, and to write "Not checked" only if that exact command fails to start, quoting its error. It was also reminded that the limit is five checker runs per story, counting the first: files mode had said "fix and rerun up to five times", which allows six. The plan now runs every step in its own fresh copy, with no stories from other steps, except D, which continues B's conversation in B's copy.

Step A ran three times with the tracker, E three times without it, and D once, after B, in B's copy. Every run was headless, the same way as trials 8 and 8b, in its own fresh copy of trial 8's starting repository. It cost about $1.96. The pass bar for shipping was A 3 of 3, E 3 of 3 and D 1 of 1. It got A 1 of 3, E 2 of 3 and D 1 of 1, so it missed. Results are from the saved outputs in `build/trial-8c/`, with the checker run again on every saved story.

| Run | Result | Checker | Tracker keys | Tracker calls |
|---|---|---|---|---|
| A-1 | Pass | 2 runs, passed | SUBS-101, SUBS-137 and SUBS-152, each with a valid live source, in the story and the reply | 5: `search_issues` "skip box", `get_issue` SUBS-152, SUBS-137, SUBS-101, SUBS-155 |
| A-2 | Fail | 2 runs, passed | SUBS-152, with a valid live source | 7: `search_issues` "skip box" and "skip next box subscriber web app", `get_issue` SUBS-152, SUBS-137, SUBS-101, SUBS-155, SUBS-131 |
| A-3 | Fail | 1 run, which couldn't open the file | SUBS-152 and SUBS-137 on Known lines with valid sources; both again in questions with the source mid-line | 4: `search_issues` "skip box", `get_issue` SUBS-152, SUBS-137, SUBS-101 |

- **A-2:** it read SUBS-101, the closed skip issue, and cited nothing from it, so it misses the plan's pass line for A.
- **A-3 and E-3:** the story was never saved. Earlier in each run, a shell command changed directory into `loupe/` to look around, and Claude Code lets a `cd` inside the project run without asking. The guide's rule, `Edit(loupe/**)`, is relative to the current directory, so after the `cd` it pointed at `loupe/loupe/` and the write was denied. In E-1 and E-2 the same kind of `cd` was joined to a `cat` and denied, so the directory didn't change. Both runs then ran the checker, quoted its error, and marked the draft "Not checked", as the 8b fix asks. In A-3, the draft's two questions had sources mid-line, which the checker would have caught.
- **E runs:** no mention of a tracker, Jira or issue search in any reply or story.
- **D-1:** the whole reply was "Loupe can't change the tracker yet." with no tool calls.
- **B-1, as setup:** 4 calls (`search_issues` "delivery address" and "address change", `get_issue` SUBS-142, SUBS-155). Its First question had the duplicate with a valid live source, and its story passed the checker. Its reply summarized the story instead of showing it, and named SUBS-142 once more without a source.
- **Every run** used shell commands such as ls, find or cat to look around, which files mode says not to do.
- **Tracker calls:** 20, all reads, matching each run's own server log. Customer email surfaced: 0.

A separate probe, outside the trial, confirmed the cause. With the allow rule passed on the command line, `Edit(loupe/**)` and `Edit(./loupe/**)` allow a write in `loupe/` until a `cd` into `loupe/`, and deny it after. `Edit(/loupe/**)` allowed none, with or without the `cd`. Claude Code's [permissions page](https://code.claude.com/docs/en/permissions.md) says a path with no prefix is relative to the current directory, and a path starting with `/` is relative to the settings source.
