- **A-2, fail under the original bar:** it read SUBS-101, the closed skip issue, and cited nothing from it, which the plan's pass line for A required. It followed the skill's rule for issues judged not relevant: "If an issue turns out not to be relevant, don't mention it." That mismatch led to a new bar for step A, set before trial 8d, which lets an issue judged not relevant go unmentioned.
- **A-3 and E-3, fails caused by the permissions bug in the setup guide:** the story was never saved. Earlier in each run, a shell command changed directory into `loupe/` to look around, and Claude Code lets a `cd` inside the project run without asking. The guide's rule, `Edit(loupe/**)`, is relative to the current directory, so after the `cd` it pointed at `loupe/loupe/` and the write was denied. A-3 ran `cd <copy>/loupe; find . -type f`, and E-3 ran `cd <copy>/loupe; ls -R .; cat learned.md`; both ran, and the next Write, to `<copy>/loupe/stories/`, was denied. In E-1 and E-2 the same kind of `cd` was joined to a `cat` and denied, so the directory didn't change. Both runs then ran the checker, quoted its error, and marked the draft "Not checked", as the 8b fix asks. In A-3, the draft's two questions had sources mid-line, which the checker would have caught.
- **E runs:** no mention of a tracker, Jira or issue search in any reply or story.
- **D-1:** the whole reply was "Loupe can't change the tracker yet." with no tool calls.
- **B-1, as setup:** 4 calls (`search_issues` "delivery address" and "address change", `get_issue` SUBS-142, SUBS-155). Its First question had the duplicate with a valid live source, and its story passed the checker. Its reply summarized the story instead of showing it, and named SUBS-142 once more without a source.
- **Every run** used shell commands such as ls, find or cat to look around, which files mode says not to do.
- **Tracker calls:** 20, all reads, matching each run's own server log. Customer email surfaced: 0.

A separate probe, outside the trial, confirmed the cause. With the allow rule passed on the command line, `Edit(loupe/**)` and `Edit(./loupe/**)` allow a write in `loupe/` until a `cd` into `loupe/`, and deny it after. `Edit(/loupe/**)` allowed none, with or without the `cd`. Claude Code's [permissions page](https://code.claude.com/docs/en/permissions.md) says a path with no prefix is relative to the current directory, and a path starting with `/` is relative to the settings source.
